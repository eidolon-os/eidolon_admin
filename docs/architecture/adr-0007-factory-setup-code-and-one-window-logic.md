# ADR-0007：出厂 Setup 码回到设备上，认领窗口只有一种逻辑

- 状态：Accepted
- 日期：2026-09-08
- 修订：[ADR-0006](adr-0006-lan-commissioning-on-every-host.md)（不推翻，收窄其第 1 条）

## Context

一台刚装好的 Orange Pi 5 Max 被手机扫到了、BLE/GATT 也连上了，但认领失败。
Host 侧的权威状态是 `claim_state=unclaimed`、`controller_grants` 0 行、
`commissioning_sessions` **0 行**——未认领、零授权、也没有任何打开的窗口。
手机报的是"它可能已被认领"，把人引向 `controller-reset`，去撤销一台 Host
根本没有的授权。（那句文案已在别处修掉。）

**没有窗口才是真原因**，而它是 ADR-0006 的直接后果：那次一并删掉了设备侧的
`EIDOLON_BOOTSTRAP_DEV_SETUP_CODE` 和"未认领时自动铸 session"的分支。树莓派当初
就是靠这两样配对成功的。于是「出厂开箱流程不存在」——这句话本来就写在
`docs/跨系统/主机认领与管理权状态机与恢复边.md:86`，只是没人把它和这次失败连起来。

重读 ADR-0006 的反对理由（该文 32–35 行），它列的是三件事：那个环境变量**没有任何
Host、ops profile 或 CI 设置过**；**读** endpoint 会顺手重铸 session，于是"一次性码
不再是一次性的"；以及"有没有窗口"变成 **mode 相关**。

**三条都是实现问题，没有一条反对"未认领的 Host 该有一个窗口"。** 第 2 条骂的是
"把固定码塞进一次性 session"这个机制，第 3 条骂的是 mode 分叉。ADR-0006 把两件
寿命不同的事塌缩成一件，然后删掉了开箱需要的那一件。

## Decision

### 1. 出厂 Setup 码保存在设备上的文件里

`/var/lib/eidolon-bootstrap/factory_setup_code`，`0600 eidolon-bootstrap`，
与 `host_identity.ed25519` 同目录、同权限、同一条制造 write-once 通道投放。

**明文。** 权衡记在这里：Host 运行期只需要哈希（`commissioning_sessions.secret_hash`
已经是哈希），存明文多出一份落地的密钥。选明文是为了设备能重新出示这个码，
以及运维上不必在两处对照。**不用环境变量**：`systemctl show -p Environment`
任何用户都能打出全部环境变量，实测如此；而 `0600` 文件不能。

文件不存在 ⇒ 不建行，回到手工 `commissioning-code`。**这一条同时是开发阶段的安全
闸门**：开发用统一码（当前 `99999990`），只要不投这个文件，就不会有常驻窗口——
不需要额外的 mode 判断，也不靠约定。

### 2. 窗口只有一种逻辑，边界只有"被消费"

一个 session 行，无期限（`expires_at` 可空，新建的行一律 `null`）：

- 装机时若有出厂码文件且 Host 未认领 → 建一行
- 认领成功 → 消费掉
- 之后加手机/换手机 → 同一条 `commissioning-code` 再建一行，**同样无期限**
- 新签一行作废上一行（至多一个开着的窗口）
- 恢复出厂 → 用文件里的码重建一行，机壳上印的码继续有效

机制、表、原子消费、`reset_epoch` 校验、8 位弱码规则全都只有一份。
`setup_code_ttl_seconds` 与 CLI 的 `--ttl-seconds` 成为遗留物。

这仍然满足 ADR-0006 的三条：这一行是**装机时建一次**，不是每次读 endpoint 重铸
（第 2 条）；不随 mode 变（第 3 条）；配置来源是制造通道投放的文件（第 1 条）。

### 3. 错码不关窗，failed_attempts 只作证据

原先 `failed_attempts >= 5 → revoked_at`。对一个无期限的行，那等于**开箱即砖**：
被吊销后没人能重签。

第一版答案是改成上锁（`locked_until`，锁 15 分钟后自解、额度归零）。**那是过度设计
并已撤回**：它需要一个新列、一条迁移、退避逻辑和一个边界语义，而它防的是「有人在
十米内连续猜 10^8 个码」——按每秒 5 次算要 115 天，且全程得待在别人家走廊里。

现在的规则只有一条：错码就是拒绝，`failed_attempts` 加一并留作证据，**没有任何东西
读它**。`revoked_at` 保留给显式撤销和新签作废旧签。

**这是一次有记录的属性变更。** ADR-0006 把 5 次失败吊销列在它保留的属性里，App 的
文案也写着「连续 5 次失败后请重新选择主机」（该文案随之作废）。放弃的是对暴力猜测
的一道限速；判断依据是攻击半径（BLE 约 10 m、需物理在场）远比八位码的熵更能约束它。
**若将来窗口延伸到更大半径（局域网、公网中继），这一条要重新算。**

## Consequences

**放弃的是"没人动手也自己关"。** 时间边界是唯一能自动关闭窗口的东西。去掉之后，
窗口只有两种关法：被消费，或被新的一次签发顶掉。残余暴露是：**有人签了码却没用**，
那个窗口就一直开着，谁拿到那个码（终端输出、或机壳）以后随时能把自己加成管理手机。

界定：至多一个开着的窗口；需要那个 8 位码；失败退避；是自己家里、自己控制的设备。
**对家用单户设备接受，换来的是只有一套逻辑。** 如果以后出现共享/出租场景，这一条
会变成问题——那时的解法不是加回全局 TTL，而是给"已认领 Host 上新签的窗口"单独加
边界，也就是回到两套。**这是现在选简单、将来可能要回头的决定，不是免费的简化。**

**硬前提：出厂码必须每台唯一。** 无期限 + 统一码 = BLE 范围内谁都能认领。由第 1 条
的"文件不存在就不建行"承担。

**`expires_at` 变可空影响签名文档**：endpoint 的 `setup_session.expires_at` 会发
`null`。读侧按"null 即无期限"宽容处理，所以两侧发布顺序不重要。
